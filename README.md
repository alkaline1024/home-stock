# home-stock

**Vibe coding project** · แอปจัดการของในบ้านที่พัฒนาร่วมกับ AI และนำมาใช้งานจริง

เว็บจดของในบ้านสำหรับมือถือและคอม ใช้รหัสผ่านเดียวกันบนเครื่องที่ต้องการเปิดตู้เดียวกัน

## ใช้งาน

- เปิดเว็บในเครื่องด้วย `npm run dev` หรือทดสอบจากมือถือในเครือข่ายเดียวกันด้วย `npm run dev:host` แล้วเปิด URL `Network` ที่แสดงในเทอร์มินัล ทั้งสองอุปกรณ์ต้องอยู่ใน Wi-Fi เดียวกัน โหมด host เปิดเซิร์ฟเวอร์บนทุก network interface และควรใช้เฉพาะเครือข่ายที่ไว้ใจได้ ใช้รหัสจาก `.local-stock/access-key.txt` เพื่อเข้าสู่ระบบ
- หลังซื้อของ กด **เพิ่มของ** กรอกชื่อ จำนวน และหน่วย ถ้ามีให้ใส่วันที่บนฉลากและรูป เลือกติดตามแบบ (EXP : วันหมดอายุ), (BBE : ควรบริโภคก่อน) หรือวันที่ตั้งใจใช้ได้
- วันที่รับเข้าเริ่มต้นเป็นวันนี้ หากชื่ออาหาร หมวด และที่เก็บตรงกับพจนานุกรม จะมีปุ่มเสนอวันที่เหนือช่องติดตามวันที่ กดแล้วระบบเลือก BBE และกรอกวันที่ให้ แก้ค่าเองได้ก่อนบันทึก วันที่นี้เป็นเพียงค่าประมาณคุณภาพ ไม่ใช่วันหมดอายุด้านความปลอดภัย
- เปิด **วันนี้** เพื่อเลือกของที่ต้องรีบใช้ หรือเปิด **ของในบ้าน** เพื่อค้นหาและปรับจำนวน
- ในหน้า **ของในบ้าน** กดรูป placeholder เพื่ออัปโหลดรูป เลือกรูปที่ยังใช้อยู่ในรายการอื่น หรือเลือกไอคอน SVG สำเร็จรูปโดยไม่อัปโหลดไฟล์ แล้วเลือกสีไอคอนและสีพื้นหลังจากพาเลตหรือกำหนดสีเองได้ก่อนกด **บันทึก** กดรูป/ไอคอนเดิมเพื่อเปลี่ยน หรือเลือก **ใช้ตัวอักษรเดิม** เพื่อเอารูปออก รูปใหม่จะถูกครอปตรงกลางเป็นสัดส่วน 1:1 ย่อไม่เกิน 1200 × 1200 พิกเซล และบันทึกเป็น JPEG quality 50% (ไฟล์ต้นฉบับไม่เกิน 25 MB)
- รูปที่ใช้ร่วมกันจะไม่ถูกลบจนกว่าจะไม่มีรายการใดใช้อยู่ คลังตัวเลือกแสดงเฉพาะรูปที่ยังใช้อยู่ ไม่รวมรูปที่ถูกลบจากทุกรายการแล้ว ไอคอนไม่ใช้พื้นที่เก็บรูป
- ไอคอนของในบ้านใช้ SVG จาก [Lucide](https://lucide.dev/icons) สร้างเป็น sprite ใน `public/item-icons.svg` พร้อมเก็บสัญญาอนุญาตไว้ที่ `LICENSES/lucide-static-LICENSE.txt`
- เปิด **รายการซื้อ** จดของที่ต้องซื้อ เมื่อซื้อจริงแล้วให้ระบุจำนวนและวันที่เพื่อรับของเข้าบ้าน
- เมนูและปุ่มจดรายการซื้อใช้ไอคอนรถเข็น ปุ่มเพิ่มใช้เครื่องหมายบวกสีพื้นหลังในวงกลมสีเดียวกับไอคอน หน้าแผนทำอาหารแยกข้อมูลและปุ่มเป็นคนละแถวบนมือถือ รวมถึงขนาด 375×667
- หน้าต่างบนมือถือแสดงเป็น bottom sheet ชิดขอบซ้าย ขวา และล่าง สูงตามเนื้อหา หากเนื้อหายาวจะเว้นด้านบนและเลื่อนอ่านได้ เปิดด้วยการสไลด์ขึ้นนุ่ม ๆ 320ms และปิดด้วยการสไลด์ลง 240ms พร้อมเฟดฉากหลัง เมื่ออุปกรณ์ตั้งค่าลดการเคลื่อนไหวจะยังสไลด์แบบเรียบง่าย โดยลดเวลาเปิด/ปิดเหลือ 180/140ms แทนการปิดแอนิเมชันทั้งหมด ลากแถบจับหรือหัวหน้าต่างลงเพื่อปิด หรือกดปุ่มปิดตามเดิม ระหว่างบันทึกจะยังปิดไม่ได้
- ในหน้า **ของในบ้าน** กด **Excel → ดาวน์โหลดไฟล์เทมเพลตนำเข้าของ** แล้วกรอกชีต **นำเข้าของ** โดยไม่เปลี่ยนหัวตาราง หน่วย หมวด ที่เก็บ และประเภทวันที่มี dropdown ใน Excel; หน่วยและที่เก็บพิมพ์ค่าใหม่ได้ รวมถึงหน่วยและที่เก็บที่ใช้อยู่แล้วในบ้าน คอลัมน์แจ้งเตือนก่อนกำหนดเว้นว่างเพื่อใช้ค่า Settings หรือใส่ 0–365 วันเฉพาะรายการได้
- กรอกชื่อของ จำนวน และหน่วย จำนวนต้องมากกว่า 0 ถึง 999999 ทศนิยมไม่เกิน 3 ตำแหน่ง หมวดว่างใช้ **อื่น ๆ** วันที่เว้นว่างได้ หรือใช้ `31/12/2026` (ปี ค.ศ.) / `2026-12-31` ประเภทวันที่ว่างใช้ **(EXP : วันหมดอายุ)** รองรับ **(BBE : ควรบริโภคก่อน)** และ **ตั้งใจใช้ภายใน** ไม่รองรับสูตรในเซลล์ ดูรายละเอียดเพิ่มเติมในชีต **วิธีกรอก**
- กด **Excel → อัปโหลดไฟล์นำเข้าของ** เลือก `.xlsx` ไม่เกิน 10 MB ตรวจพรีวิวแล้วกด **นำเข้า** หากพบข้อมูลผิดต้องแก้ไฟล์แล้วอัปโหลดใหม่ก่อน ระบบเพิ่มเป็นรายการใหม่ไม่มีรูป ไม่ทับหรือลบของเดิม รองรับรวมของเดิมไม่เกิน 2,000 รายการ อัปโหลดไฟล์เดิมซ้ำจะเพิ่มของซ้ำ
- หน้าตัวอย่างเดิมอยู่ที่ `/home-stock.html` ข้อมูลตัวอย่างแยกจากสต็อกจริง

## การดูแลเว็บบน Vercel

โปรเจกต์ใช้ Vercel Hobby กับ Private Blob ในสิงคโปร์ เซิร์ฟเวอร์ตรวจรหัสก่อนส่งข้อมูลหรือรูปให้เบราว์เซอร์ ข้อมูลเก็บใน `home-stock/stock.json` ภายใน store รูปเก็บใน `home-stock/photos/` หน้าเว็บย่อรูปก่อนส่ง

การเขียน Blob ใช้ ETag จาก `head()` กับ `ifMatch` ไม่ใช้ ETag ของ HTTP download ซึ่งอาจต่างกันเมื่อบีบอัดข้อมูล การอ่านตรวจ metadata ก่อนและหลังดาวน์โหลดแบบไม่ใช้ cache เพื่อให้เนื้อหากับเวอร์ชันตรงกัน หากข้อมูลเปลี่ยนระหว่างอ่านจะลองใหม่ โดยไม่ปิดการป้องกันเขียนทับข้อมูลจากอุปกรณ์อื่น

รหัสเข้าเว็บบนเครื่องอยู่ที่ `.local-stock/access-key.txt` ซึ่งถูกยกเว้นจาก Git สำหรับ local development ตั้งรหัสสั้นได้ แต่ production บน Vercel กำหนดให้ `HOME_STOCK_SECRET` ยาวอย่างน้อย 8 ตัวอักษร ผู้ที่มีรหัสจะเห็นและแก้ไขข้อมูลทั้งหมดของบ้านได้

หากต้องการเปลี่ยนรหัส ให้ตั้งค่า `HOME_STOCK_SECRET` ใหม่ใน Project Settings → Environment Variables (Production) ใช้รหัสสุ่มอย่างน้อย 24 ตัวอักษร แล้ว redeploy อัปเดตสำเนารหัสที่เก็บไว้เองด้วย หลัง deploy รอบใหม่ให้ลงชื่อเข้าใหม่บนแต่ละเครื่อง

หากต้องการอัปเดตโค้ดจากโฟลเดอร์ที่เชื่อมโปรเจกต์นี้แล้ว ให้ใช้ `npx vercel deploy --prod` ใช้ store เดิมเพื่อคงข้อมูล

โควตาและเงื่อนไขปัจจุบันดูได้ใน [Vercel Hobby](https://vercel.com/docs/plans/hobby) และ [Vercel Blob pricing](https://vercel.com/docs/vercel-blob/usage-and-pricing) หากใช้ Blob เกินโควตา Hobby จะระงับการเข้าถึงชั่วคราว

## รันบนเครื่องเพื่อพัฒนา

ใช้ Node.js 24 และรัน `npm run dev` จากโฟลเดอร์นี้ จากนั้นเปิด http://127.0.0.1:4177 เวอร์ชันบนเครื่องเก็บข้อมูลแยกไว้ใน SQLite ใต้ `.local-stock/` โดยใช้หน้าจอและกติกา API ชุดเดียวกับเวอร์ชันออนไลน์

โค้ดหน้าจอหลักอยู่ใน `src/app/` แยกตามส่วนงาน `public/app.js` สร้างจากไฟล์เหล่านี้ตามลำดับโดย `scripts/build-app.mjs` จึงไม่ควรแก้ `public/app.js` โดยตรง `npm run dev` ประกอบไฟล์ใหม่เมื่อแก้ไฟล์ใน `src/app/`; `npm test` และ `npm run build` ประกอบไฟล์ก่อนใช้งานด้วย

สไตล์อยู่ใน `src/styles/` และ Tailwind CLI รวมทุกส่วนเป็น `public/tailwind.css` ให้แก้ไฟล์ต้นฉบับใน `src/styles/` ตามส่วนของหน้าจอ

การย้ายสไตล์ไป Tailwind CSS กำลังทำแบบทยอยเปลี่ยน โดย `src/styles/tailwind.css` กำหนด theme และ source ที่ต้องสแกน `npm run build` สร้าง `public/tailwind.css` สำหรับ utility classes ที่ย้ายแล้ว ระหว่างนี้ CSS เดิมยังอยู่ใน `src/styles/` จนย้ายครบ

Vue 3 + Vite ใช้กับตัวเลขรายการซื้อในเมนู หน้ารายการซื้อ และหน้าเมนูที่บันทึกไว้แล้ว โดย source อยู่ที่ `src/vue/` และ `vite.config.js` สร้างไฟล์ `public/vue-pages.js` ผ่าน `npm run build` หรือ `npm run dev` ขณะย้ายหน้าจออื่นยังใช้ JavaScript เดิม

`npm run build` คัดลอก ExcelJS จาก dependency ไปยังไฟล์ static สำหรับเทมเพลตและการนำเข้า โดยโหลดจากเว็บนี้เอง ไม่ใช้ CDN; Vercel เรียก build นี้ก่อน deploy

กฎเสนอวันที่อยู่ใน `public/shelf-life-data.js` เพิ่มอาหารได้โดยเพิ่มรายการ `name`, `keywords`, `categories` และ `days` ตามชนิดที่เก็บ (`fridge`, `freezer`, `pantry`) พร้อมอ้างอิงแหล่งข้อมูล กฎที่ไม่ตรงชื่อ หมวด หรือที่เก็บจะไม่เสนอวันที่ การเปลี่ยนกฎไม่เปลี่ยนวันที่ของรายการที่บันทึกไปแล้ว

`.vercelignore` ต้องไม่ตัด `scripts/build.mjs` ออกจาก deployment เพราะ Vercel ใช้ไฟล์นี้ระหว่าง build ยกเว้นเฉพาะ `scripts/local.mjs` ซึ่งใช้รันบนเครื่องเท่านั้น

รัน `npm test` เพื่อตรวจเทมเพลต dropdown การตรวจข้อมูลนำเข้า และการจัดการข้อผิดพลาด/ข้อมูลเปลี่ยนจากอีกอุปกรณ์

## ไอคอนและทางลัดบนหน้าจอหลัก

ติดตั้งเว็บเป็นแอป (Add to Home Screen / Install app) จะได้ไอคอน home-stock และเมื่อกดค้างที่ไอคอนบน Android หรือคลิกขวาบนเดสก์ท็อป จะมีทางลัด: เพิ่มของเข้าบ้าน (เปิดฟอร์มเพิ่มของทันที), ของในบ้าน, รายการซื้อ และแผนทำอาหาร

ไอคอนทั้งหมดใน `public/icons/` และ `public/favicon.ico` สร้างจาก SVG ใน `scripts/icons.mjs` ถ้าแก้แบบให้รัน `npm run icons` แล้ว commit ไฟล์ที่ได้

## จำนวนขั้นต่ำ และการแจ้งเตือน

- ในหน้า **การตั้งค่า** ตั้งจำนวนขั้นต่ำของสินค้าแต่ละชื่อและหน่วย หน้า **วันนี้** จะแสดงรายการที่ต่ำกว่ากำหนดและปุ่มจดซื้อ
- ในหน้า **การตั้งค่า** เลือกค่าเริ่มต้นเตือนก่อนกำหนด 1, 3 หรือ 7 วัน รายการ EXP/BBE ที่ตั้ง “แจ้งเตือนก่อนกำหนดภายใน (วัน)” จะใช้ค่านั้นแทนค่าเริ่มต้น แม้ปิดค่าเริ่มต้นไว้ก็ยังเตือนเฉพาะรายการที่กำหนด อนุญาตการแจ้งเตือนในเบราว์เซอร์และบันทึกการตั้งค่าบนอุปกรณ์ เว็บจะส่งครั้งเดียวต่อวันประมาณ 09:00 น. ตามเวลาไทย โทรศัพท์ iPhone/iPad ต้องเพิ่มเว็บไปที่หน้าจอโฮมก่อนจึงจะรับ Web Push ได้
- การแจ้งเตือนบน Vercel ต้องมี `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` และ `CRON_SECRET` ใน production environment คีย์จริงเก็บใน `.local-stock/` เฉพาะเครื่องที่ตั้งค่า

## สแกนบาร์โค้ด

ในฟอร์มเพิ่มของหรือรับของเข้าบ้าน กด **สแกน** และอนุญาตใช้กล้อง ถ้าบาร์โค้ดเคยบันทึกไว้ แอปจะเติมชื่อ หน่วย หมวด และที่เก็บ จากนั้นตรวจจำนวนและวันหมดอายุของแพ็กใหม่ หน้าสแกนมีตัวปรับซูมและไฟฉายเมื่อกล้องรองรับ และใช้ตัวอ่านสองแบบพร้อมกันเมื่อเบราว์เซอร์รองรับ บาร์โค้ดใหม่กรอกชื่อครั้งแรกแล้วบันทึกเพื่อใช้ครั้งต่อไป พิมพ์เลขใต้บาร์โค้ด 8–14 หลักได้เมื่อใช้กล้องไม่ได้ กล้องทำงานบน HTTPS หรือ localhost และจะปิดเมื่อปิดฟอร์มหรือซ่อนหน้าเว็บ

## สแกนใบเสร็จ

ในหน้า **ของในบ้าน** กด **สแกนใบเสร็จ** แล้วถ่ายรูปหรือเลือกรูปใบเสร็จ แอปอ่านข้อความภาษาไทยและอังกฤษในเบราว์เซอร์ด้วย Tesseract.js โดยรูปไม่ถูกอัปโหลดไปยังเซิร์ฟเวอร์ ระบบจับคู่ชื่อสินค้ากับแถวบาร์โค้ด ไม่เพิ่มแถวราคาเป็นรายการซ้ำ และอ่านน้ำหนักสินค้าที่ชั่งเป็นกิโลกรัมได้ หากบาร์โค้ดตรงกับของที่เคยบันทึก แอปจะใช้ชื่อและรายละเอียดเดิม ตรวจชื่อ จำนวน หน่วย บาร์โค้ด หมวด ที่เก็บ และกรอกวันหมดอายุตามฉลากก่อนกด **รับเข้าบ้าน** ยกเลิกรายการที่อ่านผิดหรือกด **เพิ่มรายการ** ได้ วันหมดอายุไม่ปรากฏบนใบเสร็จจึงเว้นว่างไว้จนกว่าจะกรอกเอง รูปควรชัดและไฟล์ไม่เกิน 20 MB ระบบจะบันทึกเฉพาะรายการที่เลือก ไม่เก็บรูปใบเสร็จ

แต่ละแถวในหน้าตรวจใบเสร็จเลือกรูปหรือไอคอนและสี สแกนบาร์โค้ด ตั้งวันที่รับเข้า (เริ่มต้นวันนี้) เลือก EXP/BBE/ตั้งใจใช้ภายใน และกำหนดวันแจ้งเตือนเฉพาะรายการได้ หากชื่ออาหาร หมวด และที่เก็บตรงพจนานุกรมจะมีปุ่มเสนอวันที่ BBE เช่นเดียวกับฟอร์มเพิ่มของ ชื่อที่มีคำว่า “แช่แข็ง” จะเลือกช่องแช่แข็งให้อัตโนมัติ และเปลี่ยนเองภายหลังได้

### ให้ AI ช่วยตรวจ (เลือกใช้)

เมื่อกำหนด `GEMINI_API_KEY` ใน Vercel Production Environment Variables แล้ว redeploy หน้าตรวจใบเสร็จจะมีปุ่ม **ตรวจรายการด้วย AI** และช่องโมเดลที่แสดง Gemini 3.1 Flash-Lite เพียงตัวเดียว (ยังเปลี่ยนไม่ได้) ปุ่มนี้จะส่งรูปที่ย่อเป็น JPEG และข้อความ OCR ไปยัง Google เฉพาะเมื่อกด เพื่อเสนอรายการใหม่แทนผล OCR เดิม ผู้ใช้ยังต้องตรวจและกดรับเข้าสต็อกเอง หาก AI ล้มเหลว ผล OCR เดิมยังอยู่ และระบบไม่บันทึกรูปใบเสร็จไว้ คีย์ต้องอยู่ฝั่งเซิร์ฟเวอร์เท่านั้น ห้ามใส่ในโค้ดหรือเบราว์เซอร์ ใช้ free tier ได้ตามโควตาของ Google; ข้อมูลที่ส่งผ่าน free tier อาจถูกใช้เพื่อปรับปรุงบริการของ Google

### OpenThai 2.0 OCR (CPU, เลือกใช้)

แอปจะตรวจ `/api/receipt-ocr` ก่อนอ่านใบเสร็จ หากบริการ OpenThai พร้อม จะส่งรูป PNG ที่ปรับขนาดแล้วไปอ่าน และนำข้อความเข้า parser และหน้าตรวจรายการเดิม หากไม่ได้ติดตั้งบริการหรืออ่านล้มเหลวจะใช้ Tesseract บนอุปกรณ์อัตโนมัติ รูปที่ส่งไปบริการนี้ใช้ประมวลผลในหน่วยความจำ ไม่บันทึกลงดิสก์ ปุ่ม Gemini ยังคงเป็นการตรวจเพิ่มเติมเมื่อผู้ใช้กด

รันบน Mac/Linux ด้วย Python 3.11 ขึ้นไป:

```sh
npm run ocr:setup
npm run ocr:serve
```

เปิดอีก terminal แล้วรัน `npm run dev` หรือ `npm run host` ตามเดิม Node API จะเชื่อม `http://127.0.0.1:8788` อัตโนมัติ มือถือที่เข้าผ่าน local host ใช้ OCR บนเครื่อง Mac นี้ได้ด้วย หน้าเว็บแสดงข้อความ “กำลังอ่านใบเสร็จด้วย OpenThai OCR” เมื่อเลือก engine นี้ การติดตั้งครั้งแรกดาวน์โหลดโมเดลและ runtime จาก [iapp/OpenThai2.0-OCR-Text](https://huggingface.co/iapp/OpenThai2.0-OCR-Text) ที่ revision `39fa41bdd49f067ba41b1d9de79c06ab506d67d4` (Apache-2.0) ลง `services/openthai/model/` ซึ่งไม่เข้า Git โมเดลทำงานด้วย ONNX Runtime บน CPU ไม่ต้องมี Hugging Face API key

สำหรับ production ให้รัน `services/openthai/server.py` บนเครื่องหรือบริการ Python ที่เข้าถึงผ่าน HTTPS ได้ แล้วตั้ง environment variables:

- ฝั่ง OCR: `OPENTHAI_OCR_HOST=0.0.0.0`, `OPENTHAI_OCR_PORT=8788` (หรือพอร์ตที่โฮสต์กำหนด) และ `OPENTHAI_OCR_TOKEN` เป็น secret สุ่ม
- ฝั่ง Vercel: `OPENTHAI_OCR_URL=https://your-ocr-service.example/` และ `OPENTHAI_OCR_TOKEN` ค่าเดียวกัน จากนั้น redeploy

Vercel จะ proxy ผ่าน API ที่ตรวจ session ของผู้ใช้แล้ว จึงไม่ต้องเปิด CORS หรือส่ง token ให้เบราว์เซอร์ ตัว Python service ต้องอยู่หลัง HTTPS reverse proxy เมื่อต่อออกอินเทอร์เน็ต การใช้งานโมเดลไม่มีค่า API แต่ค่าโฮสต์ขึ้นกับบริการที่เลือก หากยังไม่ตั้ง URL บน Vercel เว็บยังใช้ Tesseract ต่อได้ บริการนี้รับทีละรูปเพื่อจำกัดการใช้หน่วยความจำ เหมาะกับการใช้ส่วนตัวในบ้าน
